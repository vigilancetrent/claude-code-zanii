**Recommendation: migrate and harden the existing ChatGPT integration inside the OpenAI provider.** The repository already has subscription login, Responses streaming and main/background query routing. Building another provider or embedding a second coding agent would add scope without solving the clarified requirement. OpenAI now documents app-owned Sign in with ChatGPT for eligible local open-source/personal tools, with eligible Plus and Pro users authorizing plan-backed inference. This is distinct from ordinary account identification and separately billed API keys. Your account's eligibility and actual successful inference remain unverified. ([OpenAI integration cookbook](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt))

The first release should support one active account in the local CLI, the project's existing tools and permission prompts, and its normal conversation lifecycle. Importing existing Codex sessions, shared membership accounts, hosted subscription proxies, multi-account management and another agent runtime are outside this milestone. Estimate delivery only after the access and protocol proof below; OAuth, persisted credentials and streaming tool execution make this a high-risk change despite the existing route.

**What the code already provides.** The actual stack is Bun, strict ESM TypeScript, React/Ink, Zod, Biome and an installed OpenAI SDK. Authentication belongs to the application; the model-provider workspace supplies shared conversion and usage helpers. Follow three existing patterns: native OpenAI auth-mode branching, shared auxiliary-query routing, and the OAuth crypto/callback helpers. No second inference SDK is inherently necessary. **Implementation sequence and acceptance gates.**

**Phase 1 — prove access and a complete tool conversation.** Register this application, authorize one eligible account, and complete text → approved harmless function → function result → final answer through `https://api.openai.com/v1/responses`. Discover models with the same authorized credential; catalog presence is not proof that inference will complete. A URL replacement alone is insufficient. Acceptance requires `response.completed`, a second reasoning-enabled request, safe cancellation, and no request reaching a paid API-key path after consent denial or subscription failure. ([Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference))

Prove protocol fidelity before widening the implementation. Subscription HTTP requests require `store:false`, `stream:true`, full array history and instructions/developer content; omit unsupported generic generation parameters. Function tools need namespaces or the supported additional-tool representation. Existing local tools remain application-executed; unavailable hosted tools must not be advertised. ([Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [function namespace schema](https://developers.openai.com/api/docs/guides/function-calling))

Preserve native output items, including opaque encrypted reasoning, rather than reconstructing state from displayed thinking. Trace stream → tool continuation → normalization → transcript write/reload → compaction. Nested message metadata is a promising existing transport, but normalization splits blocks, so native response/item IDs must prevent duplicate replay. Bind opaque state to the validated account/provider/model context and test switching each; never replay one account's encrypted items under another account. Add the smallest typed field only after this proof establishes its owner. An in-memory cache does not satisfy restart/resume. ([Reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning), [actual message type owner](/C:/Users/Hp/Desktop/project_for_all_time/zanii_claude_code/packages/@ant/model-provider/src/types/message.ts:37), [normalization](/C:/Users/Hp/Desktop/project_for_all_time/zanii_claude_code/src/utils/messages.ts:747), [transcript insertion](/C:/Users/Hp/Desktop/project_for_all_time/zanii_claude_code/src/utils/sessionStorage.ts:1061))

**Phase 2 — replace authentication internals.** Persist a stable app installation ID and the issued client registration. Use loopback authorization with fresh state, nonce and PKCE; verify signed ID-token identity, issuer, audience, expiry and nonce. Require the granted `chatgpt.tokens.use.direct` permission before inference. Keep identity-only sign-in visible without falsely enabling models. Require fresh consent for migration; never relabel existing Codex tokens. ([Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in))

Serialize token renewal across processes, atomically save rotated credentials, propagate cancellation/deadlines, and distinguish temporary refresh failures from invalid credentials. Logout clears app tokens and attempts documented revocation while preserving registration identity; report unconfirmed revocation honestly. Tokens stay out of settings, logs, fixtures and arbitrary `OPENAI_BASE_URL` hosts. Unix mode bits do not establish Windows isolation: review the actual protection used on the first supported platform. Existing storage falls back to plaintext outside macOS, so it cannot be described as encrypted cross-platform storage. ([Session lifecycle](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [storage dispatcher](/C:/Users/Hp/Desktop/project_for_all_time/zanii_claude_code/src/utils/secureStorage/index.ts:9))

**Phase 3 — complete transport and lifecycle handling.** Apply the proven request contract to both main and auxiliary calls. Prefer the installed SDK parser when it preserves the required event/error shapes; otherwise repair SSE framing, UTF-8 boundaries and reader cleanup. Treat incomplete, failed, aborted and premature-EOF states distinctly. Preserve status, code and request ID with safe diagnostics; admission failures can have nonstandard bodies. Bound retries and prevent duplicate local side effects. Permission and quota failures stop subscription requests without changing the billing mode. ([Recovery guidance](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery))

**Phase 4 — make connection, model and billing state honest.** Update `/login`, CLI status and logout together. Refresh model capabilities after account changes, preserve explicit overrides, and remove unsupported plan eligibility claims. Retain measured token usage while identifying plan-backed requests separately from API-cost estimates. `/usage` currently reaches an Anthropic-oriented utilization screen: branch before its provider-specific fetch and offer ChatGPT's Manage usage link instead of fabricated remaining percentages. ([Usage screen](/C:/Users/Hp/Desktop/project_for_all_time/zanii_claude_code/src/components/Settings/Usage.tsx:89), [cost formatter](/C:/Users/Hp/Desktop/project_for_all_time/zanii_claude_code/src/cost-tracker.ts:230))
