# Existing code architecture for ChatGPT subscription inference

## What already works architecturally and where should the integration live?

### Takeaway

This is a migration and reliability project, not a new-provider project. The repository already exposes a ChatGPT subscription login, persists an OpenAI auth-mode setting, uses a Responses adapter in the main loop, and routes auxiliary queries through the same auth/transport. Keep that architecture and replace its authentication and transport contract after validating current official SIWC eligibility.

### Cited Findings

- Stack: Bun >=1.3.0, ESM TypeScript, React 19 terminal Ink UI, OpenAI SDK ^6.34.0, Zod 4, Biome 2.4.12 and TypeScript 6.0.3. Workspaces include `packages/*`, `packages/@ant/*`, and `packages/@anthropic-ai/*`. The OpenAI SDK already exists; do not add a second HTTP library. [package.json](../../package.json:1)
- Strict TypeScript includes application and workspace TypeScript. [tsconfig.json](../../tsconfig.json:1)
- Provider precedence uses settings `modelType` first, then provider environment flags, then Anthropic first-party. Existing `openai` is the natural route; do not add a separate `codex` provider for a billing/auth-mode change. [providers.ts](../../src/utils/model/providers.ts:12)
- `/login` already offers “ChatGPT account with subscription”, with a broad Plus/Pro/Business/Edu/Enterprise claim that should be replaced with wording matching verified integration eligibility. [ConsoleOAuthFlow.tsx](../../src/components/ConsoleOAuthFlow.tsx:479)
- The existing login requests device authorization, opens the browser, completes authorization, saves `modelType: 'openai'` and `env.OPENAI_AUTH_MODE: 'chatgpt'` into user settings, applies the env value to the running process, and clears the SDK client cache. [ConsoleOAuthFlow.tsx](../../src/components/ConsoleOAuthFlow.tsx:1016)
- Settings writes merge nested objects; explicit `undefined` deletes a key. Adding the ChatGPT auth-mode value alone leaves prior model/base-URL settings in place, so model/account switching needs regression coverage. [settings.ts](../../src/utils/settings/settings.ts:473)
- After shared preprocessing the main Anthropic-shaped API dispatcher delegates to `queryModelOpenAI`. [claude.ts](../../src/services/api/claude.ts:1344)
- `queryModelOpenAI` detects ChatGPT auth mode and uses `buildResponsesRequest` -> `createChatGPTResponsesStream` -> `adaptResponsesStreamToAnthropic`; API-key mode continues using `getOpenAIClient().chat.completions.create`. [openai/index.ts](../../src/services/api/openai/index.ts:365)
- Auxiliary model calls also have a ChatGPT path. `sideQueryViaChatGPTResponses` uses the same request builder/auth/stream adapter; the provider dispatcher chooses it when auth mode is ChatGPT. This is essential because classifiers and other background queries must not fall back to an empty API key. [sideQuery.ts](../../src/utils/sideQuery.ts:566), [sideQuery dispatch](../../src/utils/sideQuery.ts:677)
- Existing tool execution remains local and permission-aware: `query.ts` passes `canUseTool` into `StreamingToolExecutor`; collected `tool_use` blocks cause follow-up turns. The tool runner evaluates hook/permission decisions before tool calls. [query.ts](../../src/query.ts:759), [follow-up turns](../../src/query.ts:1083), [toolExecution.ts](../../src/services/tools/toolExecution.ts:964)
- `@ant/model-provider` exports reusable Anthropic-to-OpenAI message/tool conversion and OpenAI usage normalization. Its client factory interface leaves auth in the main project. Do not relocate authentication into the package or rewrite the query loop. [workspace exports](../../packages/@ant/model-provider/src/index.ts:1), [client types](../../packages/@ant/model-provider/src/client/types.ts:1)
- Current model defaults and model options are already subscription-aware but static, including `gpt-5.6-sol/terra/luna`, fixed context/output budgets, and older model options. These constants are project choices, not proof of a given account's entitlements. [chatgptModels.ts](../../src/utils/model/chatgptModels.ts:7), [model picker](../../src/utils/model/modelOptions.ts:344), [small-model routing](../../src/utils/model/model.ts:62)

### Inferences

- Existing usage flow: launch the app, invoke `/login`, select ChatGPT subscription, complete browser/device sign-in, then choose `/model`. That describes wired code, not a verified successful sign-in or inference with this user's account.
- Three useful existing reference patterns are (1) native OpenAI auth-mode branching, (2) auxiliary ChatGPT Responses routing, and (3) Anthropic OAuth PKCE/callback helpers. Further patterns include provider-isolated rate-limit header parsing and host guards.
- Preserve user-visible native tools, sessions, hooks and permissions by adapting public Responses requests/events at the current boundary. Codex app-server would be a different agent runtime and is not required for the clarified subscription-inference goal.

## Which current gaps are release blockers?

### Takeaway

The current subscription route is wired to Codex-specific credentials and a private backend. It must migrate to the official app-owned subscription flow; independently, stream completion, function calling, credential lifecycle and error handling need focused proofs before release.

### Cited Findings

- The auth implementation hardcodes client ID `app_EMoamEEZ73f0CkXaXp7hrann`, issuer `https://auth.openai.com`, and device endpoints under `/api/accounts/deviceauth`. It exchanges/refreshes tokens at `/oauth/token` and refreshes with old connector scopes. It contains no requested/granted `chatgpt.tokens.use.direct` check. [chatgptAuth.ts constants](../../src/services/api/openai/chatgptAuth.ts:6), [device flow](../../src/services/api/openai/chatgptAuth.ts:197), [exchange](../../src/services/api/openai/chatgptAuth.ts:261), [refresh](../../src/services/api/openai/chatgptAuth.ts:289)
- JWT payloads are decoded and trusted for account/expiry metadata without signature/issuer/audience/nonce verification. Token endpoint response types are TypeScript assertions rather than runtime schema checks. [JWT decoding](../../src/services/api/openai/chatgptAuth.ts:74), [stored credential parsing](../../src/services/api/openai/chatgptAuth.ts:123), [token exchange](../../src/services/api/openai/chatgptAuth.ts:261)
- Credentials are written as plaintext JSON to the app's `openai-chatgpt-auth.json` with mode 0600 and best-effort chmod. Writes are not atomic, and no refresh singleflight or file lock is present; concurrent main/background refreshes may race. [storage](../../src/services/api/openai/chatgptAuth.ts:148), [refresh entry point](../../src/services/api/openai/chatgptAuth.ts:339)
- If app credentials are absent, code reads Codex's `auth.json`. Its default Codex home uses `process.env.HOME` rather than `homedir`, so Windows without HOME can resolve a relative `.codex` path. Migrating away from credential import removes this path bug and cross-app ownership problem together. [fallback path](../../src/services/api/openai/chatgptAuth.ts:52), [fallback read](../../src/services/api/openai/chatgptAuth.ts:339)
- The transport sends OAuth credentials to `https://chatgpt.com/backend-api/codex/responses` with `Origin`, `Referer`, `originator: claude-code-best` and an optional account header. This must be treated as a legacy implementation rather than the new public SIWC contract. [transport](../../src/services/api/openai/responsesAdapter.ts:471)
- The request builder emits flat `type: function` tools, converts assistant calls using only `call_id/name/arguments`, and converts tool outputs to text. It has no namespace handling, raw Responses output-item retention, or encrypted reasoning metadata. [input conversion](../../src/services/api/openai/responsesAdapter.ts:62), [tool conversion](../../src/services/api/openai/responsesAdapter.ts:132)
- Shared assistant conversion retains human-readable `reasoning_content` for DeepSeek, but the Responses conversion ignores that field and has no native Responses reasoning-item representation. The stream adapter recognizes `response.reasoning_text.delta`, but does not explicitly preserve reasoning items or their encrypted payloads. [shared converter](../../packages/@ant/model-provider/src/shared/openaiConvertMessages.ts:188), [Responses stream adapter](../../src/services/api/openai/responsesAdapter.ts:275)
- The SSE parser splits on literal `\n\n`, although it later splits data lines with a CRLF-aware regex. Consequently CRLF-separated frames never reach the JSON parser. The reader has no `finally` cancellation/release cleanup, decoder flush, or incomplete-EOF validation. [SSE parser](../../src/services/api/openai/responsesAdapter.ts:199)
- Responses errors and failed terminal events throw generic errors. Terminal success/incomplete produces Anthropic message-stop, but the adapter does not require a terminal event before EOF. The main loop explicitly assembles partial output when no message-stop arrived, while side-query collection defaults to end-turn. [terminal/error handling](../../src/services/api/openai/responsesAdapter.ts:434), [main EOF fallback](../../src/services/api/openai/index.ts:575), [side-query collector](../../src/utils/sideQuery.ts:388)
- The partial-output fallback is significant because tool blocks from a yielded assistant message can enter the local executor. A truncated stream must not commit an incomplete call or trigger a duplicate call via automatic replay. [partial assembly](../../src/services/api/openai/index.ts:575), [tool scheduling](../../src/query.ts:1083)
- HTTP failure text includes up to 500 characters of raw backend response body, and main-path errors flatten to `api_error`. New recovery must preserve structured status/code/request ID, display safe messages, and distinguish denied consent, revoked access, quota, transport failure and cancellation. [HTTP error](../../src/services/api/openai/responsesAdapter.ts:499), [main error normalization](../../src/services/api/openai/index.ts:589)
- Abort signals reach inference fetch and device polling, but initial device-code requests, code exchange, refresh and the sleep between polls have no propagated abort/deadline. Main and side-query refresh paths share the same unsynchronized auth function. [auth network calls](../../src/services/api/openai/chatgptAuth.ts:167), [polling](../../src/services/api/openai/chatgptAuth.ts:224), [inference fetch](../../src/services/api/openai/responsesAdapter.ts:490)
- CLI `auth status` marks any third-party provider as logged in even without checking its actual credentials; `/login` summary intentionally contains only Anthropic subscription/workspace auth. That cannot accurately show ChatGPT connected versus granted inference permission. [CLI status](../../src/cli/handlers/auth.ts:238), [login summary](../../src/commands/login/getAuthStatus.ts:54)
- Logout already deletes app ChatGPT auth and clears auth mode. Preserve that behavior, but never delete another app's credentials. [logout.tsx](../../src/commands/logout/logout.tsx:20)
- Main-path token accounting unconditionally computes an API USD estimate, even for subscription mode, and the generic cost formatter labels totals as cost. Token accounting should remain, but estimates must not masquerade as an actual subscription charge or unlimited usage. [query accounting](../../src/services/api/openai/index.ts:532), [cost display](../../src/cost-tracker.ts:230)
- Existing secure-storage abstraction uses macOS keychain with plaintext fallback; other platforms are plaintext. Its types are currently generated `any` stubs. It cannot simply be advertised as encrypted cross-platform credential storage. [secure storage dispatch](../../src/utils/secureStorage/index.ts:9), [plaintext implementation](../../src/utils/secureStorage/plainTextStorage.ts:1), [types](../../src/utils/secureStorage/types.ts:1)

### Inferences

- Must fix for release: app-owned auth and consent/claim verification; fixed public endpoint and token-host separation; atomic credential update and serialized refresh; terminal event validation and stream parsing; complete supported function-call round trips; shared main/auxiliary routing; accurate account/auth/billing display; no silent switch to separately charged API-key mode.
- Reasoning-item preservation, tool namespace mapping and model discovery are protocol conformance work whose exact shape depends on the official public flow. Do not merely change the private endpoint URL and leave Codex tokens and request payload unchanged.
- Multi-account UI, remote shared credential hosting, imported Codex sessions, an alternate agent runtime and broad secure-storage refactors are outside the first release. A single verified active ChatGPT profile is the smallest useful scope; keep profile identity fields internally so refresh cannot attach another account.
- Platform credential protection must be an explicit supported-platform decision. Reuse suitable storage only if it meets the official contract; adding proper OS protection can be in scope when required, while a broad cleanup of unrelated generated storage types is not.

### Gaps

- Exact SIWC API/model/tool requirements should be sourced from the parallel official-documentation research, not inferred from this legacy code.
- Preserving native Responses reasoning items across on-disk resume may require an additive provider-metadata field and verification of normalization, transcript serialization and compaction. Do not claim zero changes to persistence until that spike proves it. A memory-only cache is insufficient for restart/resume.
- The unsigned JWT parser is a finding about the current implementation. No exploit, credential exposure or actual billing error was demonstrated.

### Additional grounded scope for durable Responses state

- The actual type owner is `packages/@ant/model-provider/src/types/message.ts:37`, not the re-export in `src/types/message.ts`. `Message.message` already allows additional fields and `AssistantMessage` uses that object. Prefer a typed, optional field on the nested assistant message for provider-specific immutable output items, rather than a separate session database. [message type owner](../../packages/@ant/model-provider/src/types/message.ts:37)
- UI normalization reconstructs the outer assistant object with an explicit field list but spreads its nested `message`; outer metadata would be lost here, while nested metadata is copied to each split block. - API normalization spreads nested message fields and has an existing test proving Gemini provider metadata survives tool normalization. [API normalization](../../src/utils/messages.ts:2514), [metadata regression test](../../src/utils/__tests__/messages.test.ts:505)

Release invariant: the model receives every required opaque reasoning/output item exactly once in the correct order together with the corresponding retained function calls and outputs, including after restart or compaction; failed/interrupted turns never become executable successful calls. A fresh-session-only protocol spike can defer reload support as an explicitly temporary validation restriction, but merely starting a fresh session does not remove the requirement to preserve reasoning across tool calls within that session.
